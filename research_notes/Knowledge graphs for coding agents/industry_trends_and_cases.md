# Industry Trends and Enterprise Case Studies: Feeding Engineering Knowledge to AI Coding Agents

Research date: 2026-10-29. Search budget was limited (about 15 searches), so several figures rest on secondary coverage. Each bullet states whether a figure is company-reported, vendor marketing, or secondary/aggregator. Items marked "(prior knowledge, not re-verified this session)" come from the researcher's training data. ## Enterprise case studies: what knowledge large companies feed coding agents, how, and with what results

### Takeaway
The large firms with detailed public accounts (Uber, Stripe, Google, Morgan Stanley, Nubank) did not rely on an off-the-shelf assistant alone. Each built an internal layer that connects agents to the monorepo, internal docs, tickets and chat, and to deterministic tooling (AST rewriters, CI, sandboxed dev environments). The reported gains are largest for bounded, repetitive work such as migrations, refactors and legacy-code documentation. Productivity figures for general coding are much smaller (about 10 to 20 percent) and are mostly self-reported.

He described the result as a "hybrid workforce" in which developers supervise the agents. ### Inferences
- The common enterprise architecture has four parts: a sandboxed dev environment per agent (DevPods, Stripe isolated environments), a context layer that federates code search, docs, tickets and chat (often behind an MCP gateway), deterministic guardrails (CI, linters, AST rewriters), and human PR review as the final gate. A "knowledge graph" in practice is often this federated context layer rather than a single graph database.
- Banks favour two patterns: in-house tools built on licensed frontier models (Morgan Stanley DevGen.AI, the JPMorgan assistant, the GS AI Platform), and tightly scoped pilots of autonomous agents (Goldman with Devin). Both keep the context and model access inside firm-controlled boundaries.
- The most credible large gains (Morgan Stanley's hours, Google's migrations, Amazon's Java upgrades, Nubank's monolith split) all come from bounded transformation or understanding tasks. The general-coding gains that banks report directly are about 10 to 20 percent.

### Gaps
- No primary sources were found in this session for Citi (Citi has publicly discussed a developer copilot for about 30,000 to 40,000 developers, but this was not verified), Capital One, Meta or Microsoft context systems for coding agents.
- Goldman's actual Devin results after the pilot were not found in primary sources.
- Stripe's original blog post and Uber's primary engineering posts were not fetched directly. The figures rest on InfoQ and newsletter summaries.

## Legacy modernization: knowledge graphs and context systems for COBOL, mainframe and legacy code

### Takeaway
Legacy modernization is where knowledge graphs for code are most explicit in products. Vendors build dependency and program-flow graphs over COBOL, JCL, copybooks and data, then use LLMs to extract business rules and specifications. Producing plain-language specifications is more mature than producing fully automated translations, and every major source keeps humans in the loop.

### Cited Findings
- AWS Transform for mainframe uses agents for code, data and activity analysis. Their outputs feed a knowledge graph that users can query in natural language — [Audible podcast description (AWS episode)](https://www.audible.de/pd/B0HKL43FJ5); [AWS Transform mainframe page](https://aws.amazon.com/transform/mainframe)
- AWS Transform classifies JCL, BMS, COBOL programs and copybooks. Users can optionally enable an Amazon S3 Vectors store as a searchable knowledge base for chat — [AWS re:Post guide 2026](https://www.repost.aws/articles/ARue7jnmK4RUSaQH0NkZ4wng/mainframe-modernization-with-aws-a-complete-guide-for-2026)
- A "traceable reimagine workflow" became generally available on 16 June 2026. It covers portfolio assessment, business-rule extraction, requirements generation and code generation for z/OS COBOL and PL/I, with traceability between the steps — [AWS What's New, June 2026](https://aws.amazon.com/about-aws/whats-new/2026/06/aws-transform-mainframe-traceable-reimagine-workflow/)
- AWS published a pattern that pairs AWS Transform analysis output with Claude Code for reimagining mainframe applications. This shows a vendor pipeline in which knowledge-graph artifacts become context for a general coding agent — [AWS Migration blog](https://aws.amazon.com/blogs/migration-and-modernization/reimagining-mainframe-applications-with-aws-transform-and-claude-code/)
- AWS Transform reached general availability in May 2025 — [AWS blog](https://aws.amazon.com/blogs/migration-and-modernization/aws-transform-generally-available)
- DXC and Cognizant are named partners using AWS Transform. This is partner or vendor marketing, with no metrics — [AWS APN blog](https://aws.amazon.com/blogs/apn/accelerating-mainframe-modernization-learn-how-partners-are-leveraging-aws-transform)
- Practitioners argue that COBOL experts are still needed to define what the transformations should be — [ITPro](https://www.itpro.com/software/development/you-need-those-experts-to-even-define-what-these-transformations-are-cobol-developers-will-always-be-needed-even-as-ai-takes-the-lead-on-modernization-projects)
- Morgan Stanley's DevGen.AI focuses on legacy-code-to-English specifications (about 9 million lines by mid-2025 and about 16 million by February 2026, company-reported; see the case-studies section) — [American Banker](https://www.americanbanker.com/news/morgan-stanleys-michael-pizzi-is-27-on-the-most-innovative-people-in-finance-ranking)
- IBM watsonx Code Assistant for Z combines application discovery (IBM ADDI dependency analysis), COBOL explanation, refactoring into services, and COBOL to Java translation, with an on-premises deployment option for mainframe customers. (Prior knowledge, not re-verified this session.)
- Cognition documents a SAS-to-PySpark migration use case for Devin, which is a legacy analytics migration pattern common in banks — [Devin docs](https://docs.devin.ai/it/use-cases/examples/sas-to-pyspark)

### Inferences
- Legacy tools converge on a three-step pattern: (1) build a static structural graph (call graph, data lineage, job flows), (2) use an LLM to generate natural-language specifications and business rules attached to graph nodes, and (3) give agents that enriched graph as context for code generation and tests. Traceability from rule to code is becoming a selling point, which fits audit-heavy regulated buyers.

### Gaps
- No independent customer counts or lines-of-code metrics were found for AWS Transform or IBM watsonx Code Assistant for Z.
- Microsoft's and Google's mainframe modernization offerings (for example, Google's Mainframe Assessment Tool) were not researched within the budget.

## Trend data: surveys, analysts, and the adoption of MCP, AGENTS.md, agents and context engineering

### Takeaway
AI use among developers is close to universal (about 84 to 90 percent), but trust is falling and daily use of agents was still a minority practice in 2025. DORA's main finding, that AI amplifies the strengths and weaknesses an organization already has, supports the case for investing in context, platform and architecture rather than in tools alone. Repository-level context files (AGENTS.md and similar) and MCP servers grew quickly between 2025 and 2026, but most adoption counts come from secondary trackers.

### Cited Findings
- DORA 2025 ("State of AI-assisted Software Development", released 23 September 2025, about 5,000 respondents) found that 90 percent use AI at work, up 14 points. About 65 percent rely on it heavily. AI is now linked to higher delivery throughput, which reverses the 2024 finding, but instability challenges remain. AI "amplifies" both high-performing and struggling organizations — [Google blog](https://blog.google/technology/developers/dora-report-2025/); [dora.dev](https://www.dora.dev/research/ai); [TechRepublic](https://www.techrepublic.com/article/news-dora-ai-report-2025/)
- DORA 2025 introduced a seven-part "DORA AI Capabilities Model". It includes practices such as AI-accessible internal data, a strong version-control practice, working in small batches, a user-centric focus and quality internal platforms. Teams with loosely coupled architecture and fast feedback benefit, and tightly coupled ones see little gain — [Google Cloud announcement](https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report); [Rob Bowley critique](https://blog.robbowley.net/2025/10/01/dora-2025-ai-assisted-dev-report-some-benefit-most-dont/)
- In the Stack Overflow Developer Survey 2025, distrust of AI accuracy rose to 46 percent (from 31 percent), only about 33 percent trust AI output, and 3 percent highly trust it — [InfoWorld](https://infoworld.com/article/4031673/ai-use-among-software-developers-grows-but-trust-remains-an-issue-stack-overflow-survey.html); [The Decoder](https://the-decoder.com/developers-rely-on-ai-tools-more-than-ever-but-trust-is-slipping/)
- On agents, Stack Overflow 2025 found about 31 percent using them, 17 percent planning to and 38 percent with no plans, although some coverage reports about 14 percent daily use. 87 percent worry about agent accuracy and 81 percent about security and privacy. Among agent users, 69 percent report higher productivity but only 38 percent report better code quality — [ShiftMag](https://shiftmag.dev/stack-overflow-survey-2025-ai-5653/); [DevOps.com](https://devops.com/stack-overflow-survey-shows-ai-adoption-for-devs/)
- Gartner predicted in April 2024 that 75 percent of enterprise software engineers will use AI code assistants by 2028, up from under 10 percent in early 2023 — [Gartner press release](https://www.gartner.com/en/newsroom/press-releases/2024-04-11-gartner-says-75-percent-of-enterprise-software-engineers-will-use-ai-code-assistants-by-2028)
- Gartner's July 2025 software-engineering trends reportedly raised that figure to 90 percent by 2028 (from under 14 percent in early 2024). This comes from secondary coverage — [WebProNews](https://www.webpronews.com/gartners-2025-software-engineering-revolution-ai-assistants-to-command-90-adoption); [BizTechReports](https://www.biztechreports.com/news-archive/2025/7/25/gartner-identifies-the-top-strategic-trends-in-software-engineering-for-2025-and-beyond-gartner-july-2025)
- An academic study ("Context Engineering for AI Agents in Open-Source Software", arXiv 2510.21413, late 2025) found that only 466 repositories (about 5 percent of those sampled) had adopted any agent context-file format. This is an early baseline — [arXiv](https://arxiv.org/html/2510.21413v1)
- AGENTS.md counts vary by method. The agents.md site claims more than 60,000 projects. A June 2026 GitHub code search found about 96,600 root-level files, and a July 2026 snapshot found about 158,600 indexed matches. In one sample of active repositories, adoption rose from 13.4 percent (June) to 20 percent (September). All of these are secondary trackers — [rywalker.com](https://rywalker.com/research/agents-md-standard); [baeseokjae](https://baeseokjae.github.io/posts/feature-request-agents-md-support-agent-tools/); [Level Up Coding](https://levelup.gitconnected.com/claude-code-vs-codex-vs-cursor-vs-copilot-in-2-200-github-repos-4-in-10-claude-md-2aa1f98c003e)
- A 2026 arXiv study (2602.14690) also analyses agent configuration files across GitHub — [arXiv](https://arxiv.org/html/2602.14690)
- MCP registry counts also conflict. One analysis found about 9,650 servers in the official registry in May 2026 and about 30,375 unique servers by 10 September 2026. Glama indexed about 20,000. Anthropic cited more than 10,000 active public servers in December 2025. One tracker reports 97 million monthly SDK downloads by May 2026. All of these are secondary — [dev.to registry analysis](https://dev.to/amareswer/the-mcp-registry-by-the-numbers-38nc); [gentic.news](https://gentic.news/article/mcp-hits-10k-servers-97m-monthly); [tooldirectory.ai](https://tooldirectory.ai/blog/state-of-mcp-servers-2026)

### Inferences
- The industry has moved from autocomplete (2022 to 2024) to IDE chat and agent modes (2025) and then to background or asynchronous agents that open PRs (Stripe Minions, Uber Minion, Devin, Google's migration agents, 2025 to 2026). Each step raises the value of curated, machine-readable context, because an agent working alone cannot ask a colleague.
- DORA's capability model and the falling trust in Stack Overflow's data point the same way. The lever enterprises control is the quality and accessibility of internal context (documentation, platforms, architecture), and that work is increasingly owned by platform engineering teams (Uber's MCP gateway and agent builder are an example).
- The word "context engineering" now appears in academic work and vendor messaging. This session did not find a formal Gartner or Forrester definition of the discipline.

### Gaps
- JetBrains State of Developer Ecosystem 2025 and GitHub Octoverse 2025 figures were not retrieved because of the search budget.
- No Gartner or Forrester primary research on "context engineering" or on platform teams owning agent context was found. This may sit behind paywalls.
- Spec-driven development adoption (GitHub Spec Kit, AWS Kiro) was not quantified in this session.

## Market moves 2025-2026: funding, acquisitions, AAIF, and vendor convergence

### Takeaway
The market consolidated around a few agent vendors with very large valuations (Cognition with Windsurf, Anysphere's Cursor). Interoperability standards moved to neutral governance under the Linux Foundation's Agentic AI Foundation (MCP, AGENTS.md, goose, and later agentgateway). Bloomberg was a founding Platinum member, and major banks have since joined, so financial services has a direct seat in setting these standards.

### Cited Findings
- AAIF launched on 9 December 2025 under the Linux Foundation. Its founding projects were Anthropic's MCP, OpenAI's AGENTS.md and Block's goose. The Platinum members were AWS, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft and OpenAI — [SiliconANGLE](https://siliconangle.com/2025/12/09/linux-foundation-announces-agentic-ai-foundation-joined-anthropic-openai-block/); [RCPmag](https://rcpmag.com/Articles/2025/12/09/Linux-Foundation-Unites-Major-Tech-Firms.aspx); [OpenSourceForU](https://opensourceforu.com/2025/12/anthropic-openai-block-move-agentic-ai-infrastructure-to-open-source-governance-under-linux-foundation/)
- AAIF membership reportedly reached 146 organizations by 24 February 2026 and 247 by August 2026, with Alibaba, Visa and Wells Fargo joining as Gold members. agentgateway became the fourth hosted project on 4 June 2026, and the MCP Dev Summit series was donated to AAIF. All of this comes from a secondary wiki, and no primary roster was found — [Latent Space wiki](https://latent.space/wiki/aaif/)
- An AGNTCon/MCPCon Europe 2026 recap describes the AAIF event circuit — [lucaberton.com](https://lucaberton.com/blog/agntcon-mcpcon-europe-2026-recap-takeaways/)
- Cognition acquired Windsurf in July 2025, after OpenAI's planned acquisition collapsed and Google licensed the technology and hired Windsurf's leaders. Cognition inherited about $82M ARR and more than 350 enterprise customers — [CO/AI](https://getcoai.com/news/cognition-raises-300m-at-10b-valuation-after-acquiring-windsurf/)
- Cognition's valuations rose as follows: $10.2B in September 2025; more than $1B raised at $26B post-money in May 2026, with a run-rate revenue of $492M; and Bloomberg-reported early talks at about $40B, with no deal confirmed — [SiliconANGLE May 2026](https://siliconangle.com/2026/05/27/vibe-coding-startup-cognition-doubles-valuation-new-1b-round/); [The Next Web](https://thenextweb.com/news/cognition-just-raised-1-billion-at-a-26-billion-valuation-and-90-of-its-own-code-is-written-by-its-ai); [RuntimeWire](https://runtimewire.com/article/cognition-funding-talks-40-billion-valuation-scott-wu)
- Anysphere (Cursor) raised $2.3B at $29.3B post-money in November 2025. In April 2026 it was reportedly in talks for at least $2B at about $50B (a16z, Thrive, Nvidia). This session did not confirm that the round closed. A reported SpaceX partnership with a possible $60B acquisition angle is unverified — [The Next Web, April 2026](https://thenextweb.com/news/cursor-anysphere-2-billion-funding-50-billion-valuation-ai-coding)
- Vendors are converging on the same mechanisms. Anthropic introduced Agent Skills (folders of instructions, scripts and resources that load on demand) in October 2025 and published them as an open specification in December 2025, and other agent vendors (OpenAI Codex, GitHub Copilot, Cursor) added support for SKILL.md-style skills. Most major coding agents now read AGENTS.md and act as MCP clients. (Prior knowledge, not re-verified this session.)

### Inferences
- The context-delivery stack for coding agents is being standardized in layers. AGENTS.md carries static repository instructions, Skills package procedural knowledge that loads on demand, MCP provides live tool and data access, and gateways such as agentgateway add policy and audit. This lets enterprises build one internal context layer and serve it to several vendors' agents, which reduces lock-in. Banks are buying several vendors at once (for example, JPMorgan uses both Copilot and Claude).

### Gaps
- Other 2025-2026 acquisitions in the context and code-intelligence space were not researched within the budget. These include code-search or code-graph vendors and deals by Atlassian, GitLab or JetBrains.
- No primary AAIF membership list was fetched.

## Regulated-industry concerns: data residency, permission-aware retrieval, auditability, model risk, and self-hosting

### Takeaway
Regulated firms want context engines and agent control planes that run in their own cloud tenancy or on premises, that respect source-system permissions, and that write immutable audit logs. US model-risk guidance changed in 2026: secondary sources report that SR 11-7 was superseded by SR 26-2, which they say leaves generative and agentic AI to each bank's own governance. This needs primary confirmation. Little public material addresses coding agents specifically, as opposed to customer-facing AI agents.

### Cited Findings
- Several sources report that on 17 April 2026 the Fed, OCC and FDIC issued SR 26-2 and OCC Bulletin 2026-13, superseding SR 11-7. A footnote reportedly puts generative and agentic AI outside the scope and defers to each bank's governance. Traditional quantitative models stay under model-risk management. These are vendor blogs, and the primary text was not checked — [Arthur.ai](https://www.arthur.ai/column/ai-agent-compliance-tools-for-banks-a-guide); [Lyzr research (October 2026)](https://www.lyzr.ai/?p=149986)
- Other sources still treat agents as models under SR 11-7, which conflicts with the reports above. These sources probably predate the April 2026 change — [Sardine](https://www.sardine.ai/blog/agentic-ai-in-banking); [ibl.ai](https://ibl.ai/blog/sr-11-7-compliant-ai-for-banks)
- Vendors argue that cloud-managed agent services leave residency gaps at system boundaries and that self-hosted control planes are the defensible choice for multi-model or air-gapped workloads. This is vendor marketing — [Prediction Guard](https://predictionguard.com/blog/ai-agent-deployment-in-financial-services-compliance-data-residency-and-regulatory-requirements); [Goabacus](https://goabacus.co/blog/complete-guide-on-premise-ai-banks)
- Frontier-model API terms often include a data-residency clause but no audit-rights clause, which matters for third-party risk management under OCC guidance. This is vendor commentary — [Diagrid 2026 checklist](https://www.diagrid.io/infrastructure/2026-compliance-checklist-ai-agents-banking)
- Recommended controls include immutable audit logs, 72-hour incident-notification clauses in vendor contracts, and FFIEC audit readiness, together with GLBA and the EU AI Act — [Sardine](https://www.sardine.ai/blog/agentic-ai-in-banking)
- One vendor describes tracing coding-agent harnesses (for example, Claude Code and Cursor) as monitored channels in bank agent governance. This is vendor marketing — [Arize](https://arize.com/resources/ai-agent-governance-banking/)

### Inferences
- For a capital-markets firm, an internal context system for coding agents probably needs five properties. It should inherit access controls from source systems at query time (permission-aware retrieval, so an agent cannot surface code or documents the user cannot see). It should be deployable inside the firm's VPC or on premises. It should log every retrieval and tool call to an immutable store. It should sit behind a policy gateway, such as an MCP gateway or agentgateway. And it should produce traceable links from specifications to code that auditors can follow, as AWS's traceable reimagine workflow advertises.
- If SR 26-2 does exclude generative and agentic AI, banks will need to define their own governance for coding agents. That would likely put the work under existing SDLC, change-management and third-party-risk controls rather than formal model validation. This is an inference that depends on confirming the primary text.
