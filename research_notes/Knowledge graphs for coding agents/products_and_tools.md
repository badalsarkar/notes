# Products and Tools That Build Engineering Knowledge Graphs or Context Engines for Coding Agents

Research date: 2026-10-29. Evidence labels used below: **[V]** means a vendor claim (the company's own site, docs, press release or blog). **[I]** means an independent or third-party source. **[A]** means a low-quality aggregator or directory site, which should be weighted lightly. The researcher made about 30 search and fetch calls, so the catalog is broad but shallow per product. Many details come from search-result summaries rather than full page reads.

## Q1. Commercial context engines: what each one is, how it stores knowledge, what it ingests, how it delivers context, freshness, scale, pricing, strengths, weaknesses and customers

### Takeaway
By late 2026 almost every commercial context engine exposes its index to third-party coding agents (Claude Code, Cursor, Codex, Copilot) through an MCP server, so the market has shifted from "our IDE assistant" to "our context layer for any agent". The products split into code-structure engines (Sourcegraph, Augment, Moderne, Greptile, Qodo, Bito) and organizational-knowledge engines that add tickets, PRs, chat and docs (Unblocked, Atlassian Teamwork Graph, Glean, Tabnine, Factory). Nearly all quality and scale numbers are vendor-reported, and independent benchmarks are scarce.

### Cited Findings

#### Sourcegraph (code search, SCIP code graph, Cody, MCP server) and Amp
- **What it is.** Sourcegraph's MCP page describes cross-repository code intelligence for agents, with navigation backed by SCIP, which is Sourcegraph's open code-intelligence indexing standard. [V] — [Sourcegraph MCP](https://sourcegraph.com/mcp)
- **How knowledge is stored.** Precise go-to-definition and find-all-references across repositories come from SCIP indexes. Keyword, regex and natural-language search come from the Sourcegraph search index. [V] — [Sourcegraph MCP](https://sourcegraph.com/mcp)
- **Delivery.** The MCP server is served per instance at `/.api/mcp` over Streamable HTTP, with OAuth or API-key authentication. Its tools include code search, file and repository reading, code navigation, commit and diff history, and Deep Search. A third-party listing names tools `keyword_search` and `nls_search`. [V]/[A] — [Sourcegraph MCP changelog](https://sourcegraph.com/changelog/sourcegraph-mcp-server); [Cequence AI gateway docs](https://docs.aigateway.cequence.ai/docs/remote-mcp-servers/sourcegraph)
- **Licensing conflict.** The changelog describes the MCP server as experimental and Enterprise-only. A docs preview page says it requires Sourcegraph 6.8+ and is available on all deployment types. An independent 2026 survey calls it "Enterprise and sales-gated" with no public install docs. [V]/[I] — [Sourcegraph changelog](https://sourcegraph.com/changelog/sourcegraph-mcp-server); [Sourcegraph docs preview](https://sourcegraph-docs-au3cn58kn-sourcegraph-f8c71130.vercel.app/api/mcp); [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **Cody pivot.** Sourcegraph discontinued Cody Free and Cody Pro in July 2025, and Cody is now enterprise-only. [A] — [usagepricing.com](https://usagepricing.com/blueprint/activity/2026-06-08-sourcegraph-cody-enterprise-only); [aiwiki](https://aiwiki.ai/wiki/sourcegraph_cody)
- **Amp spin-out.** Amp, Sourcegraph's agentic coding tool, was spun off as a separate company in December 2025. Quinn Slack and Beyang Liu moved to Amp, and Dan Adler became Sourcegraph's CEO. [I] — [Wikipedia: Sourcegraph](https://en.wikipedia.org/wiki/Sourcegraph); [Tessl blog](https://tessl.io/blog/sourcegraph-spins-out-ai-coding-agent-amp-as-a-standalone-company/)
- **Conflict on the Amp entity name.** Sources variously name the new company "Amp Inc." or "Amp Frontier Corporation", with a date of December 2, 2025. This was not verified against a primary announcement. [A] — [latent.space wiki](https://latent.space/wiki/amp-code/); [vibecodehq review](https://vibecodehq.pages.dev/reviews/sourcegraph-cody-review-2026)
- **Strengths and weaknesses.** The strength is compiler-accurate cross-repository navigation at enterprise scale. The weakness is that it is gated behind Enterprise sales, and it indexes code rather than tickets, chat or design docs. The independent survey recommends it only "for repos already on Sourcegraph Enterprise". [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)

#### Augment Code Context Engine and Context Engine MCP
- **What it is.** Context Engine MCP became generally available on February 6, 2026, and brings Augment's semantic code search to any MCP-compatible agent. [V] — [Augment changelog](https://www.augmentcode.com/changelog/context-engine-mcp-in-ga); [Augment blog](https://www.augmentcode.com/blog/context-engine-mcp-now-live); [SiliconANGLE](https://siliconangle.com/?p=730231)
- **Storage and freshness.** There are two modes. Local mode runs the Auggie CLI as a stdio MCP server that indexes the working directory in real time with no manual sync. Remote mode automatically indexes repositories connected through the Augment GitHub App. [V]/[I] — [Augment MCP docs](https://docs.augmentcode.com/context-services/mcp/overview.md); [rywalker.com analysis](https://rywalker.com/research/augment-context-engine)
- **Sources ingested.** Third-party reviews say the semantic index covers code, docs, dependencies and git history. [A] — [theplanettools.ai](https://theplanettools.ai/tools/augment-code)
- **Supported agents.** Augment documents setup for Claude Code, Codex, Cursor, Zed, GitHub Copilot, Kilo Code, Gemini CLI and Roo Code. An official Claude Code plugin also exists. [V] — [Augment Context Engine MCP product page](https://www.augmentcode.com/product/context-engine-mcp); [skillselion listing](https://skillselion.com/plugin/augmentcode/context-engine-plugin)
- **Quality claims.** Augment reports 30–80% quality improvements across leading agents, and a headline 70%+ improvement for Claude Code, Cursor and Codex. These are vendor measurements. [V] — [Augment blog](https://www.augmentcode.com/blog/context-engine-mcp-now-live)
- **Scale claims.** Augment's marketing claims 1M+ files and sub-200 ms latency, which the researcher could not verify. One tester reported about 8 minutes of initial indexing on a monorepo of about 150K files. [V]/[A] — [theplanettools.ai](https://theplanettools.ai/tools/augment-code)
- **Pricing.** Augment uses credit-based pricing. Third-party listings give Indie at $20/month (40,000 credits), Standard at $60/month (130,000 credits), Max at $200/month (450,000 credits), and custom Enterprise pricing. An average Context Engine MCP query costs about 40–70 credits according to Augment's docs. [V]/[A] — [Augment credit pricing](https://docs.augmentcode.com/models/credit-based-pricing); [Augment MCP docs](https://docs.augmentcode.com/context-services/mcp/overview.md); [costbench](https://costbench.com/software/ai-coding-assistants/augment-code)
- **Weakness.** Users have complained about credit consumption and pricing changes, including one report of 51,072 credits used in a single day. [A] — [prospeo.io](https://prospeo.io/s/augment-pricing-reviews-pros-and-cons)

[A] — [Mammoth Times press release](https://business.mammothtimes.com/mammothtimes/article/gnwcq-2025-11-5-tabnine-launches-enterprise-fit-agentic-ai-powered-by-its-enterprise-context-engine); [everydev.ai](https://www.everydev.ai/tools/tabnine-enterprise-context-engine)
- **Acquisition.** Tricentis announced on July 30, 2026 that it is acquiring Tabnine and will integrate the Enterprise Context Engine into its Agentic Quality Engineering Platform. Deal terms and closing status were not found. [V]/[I] — [Tricentis news](https://www.tricentis.com/news/tricentis-acquires-tabnine); [Business Wire](https://secure.businesswire.com/news/home/20260730388427/en/Tricentis-Acquires-Tabnine-to-Further-Scale-Agentic-Quality-Engineering-for-the-Enterprise); [SD Times](https://sdtimes.com/ai/tricentis-acquires-tabnine-to-further-scale-agentic-quality-engineering-for-the-enterprise/)
- **Strength.** The strength is air-gapped and on-prem deployment for regulated customers. The weakness is that its roadmap may be redirected toward testing after the Tricentis acquisition, which is an inference rather than a reported fact.

- **Version and pricing.** One review says Greptile v4 shipped on March 5, 2026, and lists pricing at $30 per developer per month with no free plan. [A] — [dev.to review](https://dev.to/jovan_chan_9500711396d4e6/greptile-review-2026-82-bug-catch-rate-the-1review-trap-and-who-should-pay-30month-4jao)

[A] — [dev.to alternatives](https://dev.to/pyor/greptile-alternatives-in-2026-an-honest-comparison-k4); [aicodereview.cc](https://aicodereview.cc/tool/greptile/)

#### Unblocked
- **What it is.** Unblocked's MCP server gives coding agents organizational context from PR history, messaging threads, issue trackers and documentation. It is generally available with a CLI and a cookbook of recipes. [V] — [Unblocked MCP overview](https://docs.getunblocked.com/unblocked-mcp/mcp-overview); [Unblocked blog](https://getunblocked.com/blog/unblocked-context-engine-for-agents)

[V] — [Unblocked: Building a Context Engine on MCP](https://getunblocked.com/blog/building-a-context-engine-on-mcp/); [Unblocked: Glean MCP vs a Context Engine](https://getunblocked.com/blog/glean-mcp-vs-context-engine/)

#### Moderne (OpenRewrite Lossless Semantic Trees)
- **Storage.** The Lossless Semantic Tree (LST) is a type-attributed tree of source code that is built by invoking the repository's real build toolchain (Gradle, Maven and others). It powers semantic tools such as `find_types`, `find_methods`, `change_type` and OpenRewrite recipe execution. [V] — [Moderne MCP overview](https://docs.moderne.io/user-documentation/agent-tools/mcp/overview/)
- **Delivery.** A local MCP server ships in the Moderne CLI (`mod mcp`) and communicates over stdio without transmitting code. A remote MCP server runs recipes against repositories already ingested into a Moderne tenant. Moderne Trigrep is a fast text index built from LSTs. [V] — [Moderne MCP docs](https://docs.moderne.io/user-documentation/agent-tools/mcp); [Moderne MCP security](https://docs.moderne.io/user-documentation/agent-tools/mcp/security)
- **Supported agents.** Claude Code, Windsurf, Cursor, GitHub Copilot, Amp and Codex are supported, configured with `mod config agent-tools install`. [V] — [Moderne MCP overview](https://docs.moderne.io/user-documentation/agent-tools/mcp/overview/)
- **2026 changes.** Moderne launched Prethink in February 2026, which derives structured agent knowledge from the LST, and added Python to the LST alongside Java and JavaScript/TypeScript. [V] — [Business Wire](https://www.businesswire.com/news/home/20260210110758/en/); [techintelpro](https://techintelpro.com/news/ai/agentic-ai/moderne-adds-python-support-to-agent-tools-platform-with-lossless-semantic-tree)
- **Strength and weakness.** The strength is compiler-accurate types and deterministic, large-scale refactoring. The weakness is that language coverage is limited to languages with an LST implementation, and the build toolchain must run to produce the tree.

### Inferences
- The common delivery mechanism is now MCP. Every product in this list except Bloop (shut down) and CodeSee (absorbed) exposes context through MCP or plans to, which makes the context engine an interchangeable layer beneath any agent.
- Two product categories are converging. Code-structure engines (Sourcegraph, Moderne, Greptile) are precise about code but ignore tickets and chat. Organizational engines (Atlassian, Glean, Unblocked) cover tickets and chat but treat code as text. Tabnine and Bito explicitly claim to join both in one graph.
- Pricing is moving to usage and credits (Augment) or Enterprise-only gating (Sourcegraph, Qodo), so self-serve options for individuals are shrinking.

### Gaps
- Independent, head-to-head benchmarks of these context engines on the same tasks were not found. All quoted percentages (Augment 30–80%, Qodo 80% on DeepCodeBench, Bito 47% token reduction, Atlassian "nearly half") are vendor-reported.
- Named customers were found only for Factory. Customer lists for Augment, Qodo, Unblocked, Bito, Moderne and Greptile were not collected.
- The internal storage design of DeepWiki, Unblocked and Glean code search (graph versus vector versus hybrid) is not publicly documented in the sources found.
- Pricing for Unblocked, Qodo Context Engine, Bito AI Architect, Glean and Atlassian Teamwork Graph was not found.
- Whether Tricentis has closed the Tabnine acquisition was not confirmed.

## Q2. Graph and knowledge infrastructure used for code

### Takeaway
General-purpose graph databases and GraphRAG frameworks (Neo4j, Memgraph, FalkorDB, Microsoft GraphRAG, LightRAG, Graphiti, Cognee) are the building blocks underneath many open-source code-graph tools, but none of them is a code context engine out of the box. Two notable 2025–2026 events are the archiving of Kuzu after Apple acquired it, and widely reported evidence that LLM-extracted GraphRAG indexing is about 1000 times more expensive than a vector index.

### Cited Findings
- **Neo4j.** CodeGraphContext stores functions, classes, calls and imports in Neo4j, which shows Neo4j being used as a code-graph backend. An independent survey notes that it requires a Neo4j 5.x instance plus embedding infrastructure. [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **Memgraph.** code-graph-rag (vitali87) parses code with Tree-sitter, stores the structure in Memgraph, and answers natural-language questions by generating Cypher queries. [A] — [PyPI: code-graph-rag](https://pypi.org/project/code-graph-rag); [mdskills listing](https://www.mdskills.ai/mcp-servers/code-graph-rag)
- **FalkorDB Code Graph.** FalkorDB's Code Graph is a Python module that builds a graph of code entities and relationships, and uses LLMs to infer relationships and generate descriptions. FalkorDB lists Graphiti, Cognee, LangChain and LlamaIndex as integrations. [V] — [FalkorDB code-analysis use case](https://falkordb.com/use_cases/code-analysis); [FalkorDB FAQ](https://www.falkordb.com/?p=6677)
- **Graphiti and Zep.** Graphiti is a Python framework for temporally aware, multi-tenant knowledge graphs, and it powers the core of Zep's agent memory layer. FalkorDB contributed a native backend as the project approached 14,000 GitHub stars. [V] — [Zep blog](https://blog.getzep.com/graphiti-knowledge-graphs-falkordb-support/); [FalkorDB docs: Graphiti](https://docs.falkordb.com/agentic-memory/graphiti.html)
- **Cognee.** Cognee is a memory framework that pairs graph storage with vector storage. FalkorDB can serve as both the graph store and the vector store. FalkorDB's FAQ says Cognee emphasizes hybrid storage and search types, while Graphiti emphasizes temporal reasoning. [V] — [FalkorDB docs: Cognee](https://docs.falkordb.com/agentic-memory/cognee)
- **Kuzu.** Apple acquired Kuzu, an embeddable MIT-licensed graph database. The GitHub repository was archived on October 10, 2025, and the company website went offline. The acquisition was publicly confirmed in February 2026 through an EU acquisitions list. A community fork named LadybugDB continues development. [I] — [The Register](https://www.theregister.com/2025/10/14/kuzudb_abandoned/); [BetaKit](https://betakit.com/apple-strikes-deal-to-acquire-canadian-database-software-startup-kuzu/); [University of Waterloo](https://cs.uwaterloo.ca/news/waterloo-based-graph-database-start-up-kuzu-acquired-apple); [PuppyGraph](https://www.puppygraph.com/blog/what-is-kuzudb)
- **Microsoft GraphRAG cost.** A secondary analysis of Microsoft's LazyGraphRAG benchmark says original GraphRAG indexing cost about 1000 times a naive vector index (about $1,544 versus about $1.45 per million tokens). LazyGraphRAG reportedly reaches comparable quality at about 0.1% of that indexing cost. [I] — [beri.net](https://www.beri.net/article/graphrag-vs-vector-rag-indexing-query-cost-lightrag-lazygraphrag-2026)
- **GraphRAG freshness limitation.** GraphRAG is batch-oriented and historically required full re-indexing when the corpus changed. LightRAG introduced incremental processing, but it cannot detect communities and may miss complex multi-hop relationships. [A] — [aicoolies comparison](https://aicoolies.com/comparisons/lightrag-vs-graphrag); [GraphRAG best practices (mintlify mirror)](https://www.mintlify.com/microsoft/graphrag/guides/best-practices)
- **Conflict on LightRAG savings.** One comparison claims a 10x reduction in indexing tokens, while others say indexing costs are similar and the savings come at query time. [A] — [aicoolies comparison](https://aicoolies.com/comparisons/lightrag-vs-graphrag); [lilys.ai](https://lilys.ai/en/notes/get-your-first-users-20260207/graphrag-lightrag-comparison)

### Inferences
- For code, LLM-extracted GraphRAG is a poor fit as the primary index, because code already has a deterministic structure that parsers can extract cheaply and exactly. GraphRAG-style extraction is more useful for unstructured sources such as ADRs, design docs and Slack threads.
- Temporal graphs (Graphiti) address a real need for engineering knowledge, namely "what was true when", such as which decision superseded which. No coding-specific product built on Graphiti was found, however.
- The Kuzu archiving is a concrete dependency risk for tools that embed a graph database. Embedded tools that chose Kuzu must now pin version 0.11.3 or migrate to a fork.

### Gaps
- Official Neo4j "codebase knowledge graph" reference architectures and the Neo4j GraphRAG package were not fetched.
- Memgraph's own code-graph offerings beyond hosting code-graph-rag were not researched.
- No independent evaluation of Graphiti or Cognee as memory for coding agents was found.

## Q3. Open-source code-graph and agent tools

### Takeaway
The open-source landscape in 2026 is crowded with MCP servers that build a code graph with Tree-sitter (codebase-memory-mcp, code-graph-mcp, GitNexus, code-graph-rag, CodeGraphContext, Potpie) or that wrap real language servers (Serena). The LSP-based Serena is the most widely adopted at about 25K stars. Licensing and operational weight vary widely: GitNexus is non-commercial, CodeGraphContext and code-graph-rag need a graph-database server, and several smaller servers are already archived.

### Cited Findings
- **Serena (Oraios AI).** Serena is an MIT-licensed MCP server that gives Claude Code, Codex and other agents language-server-backed retrieval, editing and refactoring tools across 40+ languages. Its tools include `find_symbol`, `find_referencing_symbols` and `replace_symbol_body`, and a JetBrains plugin can replace the language servers. [A] — [rywalker.com research](https://rywalker.com/research/serena); [pantheon-org analysis](https://pantheon-org.github.io/agentic-context/analysis/oraios-serena/)
- **Serena adoption.** Star counts range from about 24.2K (TypingMind) to 25,173 (DEV Community). Older pages show 13.8K–17.2K. [A] — [DEV Community](https://dev.to/_cbd692d476c5faf3b61bcf/serenas-5-hidden-uses-that-give-your-ai-coding-assistant-real-ide-intelligence-25k-stars-4621); [TypingMind](https://www.typingmind.com/mcp/serena)
- **GitNexus.** GitNexus builds a Tree-sitter code graph with BM25 and optional embeddings, stored in a `.gitnexus/` directory (1.2 GB for the Emacs tree), and exposes it in a browser UI, a CLI and an MCP server with 16–19 tools. It is licensed under PolyForm Noncommercial 1.0.0, so it is not open source for commercial use. It extracted zero functions from Clojure, and its `analyze` command writes `AGENTS.md`, `CLAUDE.md` and skill files into the repository unless `--index-only` is used. [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **GitNexus criticism.** An aggregator's reviewers say GitNexus falls apart on polyglot repositories, generated code and large monorepos, where the graph "becomes a hairball". [A] — [shiporskip.io](https://shiporskip.io/compare/claude-context-zilliztech-mcp-codebase-search-claude-code-2026-vs-gitnexus-zero-server-code-knowledge-graph-browser-rag-2026)
- **CodeGraphContext.** CodeGraphContext indexes code into a Neo4j graph of functions, classes, calls and imports. It requires a Neo4j instance and embedding infrastructure, and it is described as "pure graph". [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **code-graph-rag.** code-graph-rag is MIT-licensed. It uses Tree-sitter and Memgraph, runs as an MCP server via `cgr mcp-server`, can edit code, and added UniXcoder embeddings for semantic function search. It requires Python 3.12+, Docker for Memgraph, cmake and ripgrep. [A] — [PyPI](https://pypi.org/project/code-graph-rag); [awesome.ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2Fvitali87%2Fcode-graph-rag)
- **codebase-memory-mcp.** codebase-memory-mcp is a single static C/C++ binary that uses Tree-sitter across 158 languages with a persistent graph. One review reports about a 99% token reduction on "where is this called from?" queries, but the methodology is vendor-published. [I]/[A] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/); [dev.to review](https://dev.to/andrew-ooo/codebase-memory-mcp-review-99-token-cut-for-code-agents-3d81)
- **code-graph-mcp (sdsrss).** code-graph-mcp is an MIT-licensed Rust tool that builds an AST knowledge graph with semantic search, call graphs and HTTP route tracing. [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **CodeGraph (Colby McHenry).** CodeGraph is an open-source MCP server that gives agents a pre-indexed, AST-based knowledge graph. A review reports five structural queries costing about 3,400 tokens via the graph versus about 412,000 via grep-and-read, but the methodology was not published. [A] — [dev.to CodeGraph review](https://dev.to/andrew-ooo/codegraph-review-pre-indexed-knowledge-graph-for-ai-agents-af1)
- **Potpie.** Potpie is Apache-2.0 licensed. It turns codebases into a knowledge graph of component relationships, and agents query it with vector similarity and node lookup. It works best with Python, JavaScript and TypeScript, and is now CLI-first (`potpie resolve`, `potpie search`) with a spec-driven development focus. [A] — [Potpie README](https://cdn.jsdelivr.net/gh/potpie-ai/potpie@main/README.md); [gittrend](https://gittrend.io/repo/potpie-ai/potpie)
- **Blarify.** Blarify builds a code graph and supports SCIP, which its package page claims gives up to 330 times faster reference resolution than LSP. [V] — [PyPI: blarify](https://pypi.org/project/blarify/1.3.5/)
- **Nuanced.** Nuanced provides function call-graph MCP servers. The Python version (`nuanced-mcp`) offers call-graph retrieval and change-impact analysis, and the TypeScript npm package `@nuanced-dev/nuanced` serves TypeScript call graphs to Cursor and Claude Code. The npm package shows very low weekly downloads. [A] — [playbooks.com](https://playbooks.com/mcp/mattmorgis-nuanced); [socket.dev](https://socket.dev/npm/package/@nuanced-dev/nuanced)
- **Aider repo map.** Aider extracts definition and reference tags with Tree-sitter, builds a file graph from shared identifiers, ranks it with PageRank personalized to the files in the chat, and emits a token-budgeted text map. It does not use embeddings. [A] — [repo-mapper spec](https://docs.rs/crate/repo-mapper/0.0.1/source/SPEC.md); [pyshine Aider overview](https://pyshine.com/aider/)
- **Lightweight alternatives and archived tools.** `probe` (Rust, ripgrep plus Tree-sitter, built-in MCP) was the independent surveyor's first choice for a light install. `wrale/mcp-server-tree-sitter` was archived on May 21, 2026, and the standalone `semgrep/mcp` repository was archived on October 28, 2025. Joern-based code-property-graph servers (codebadger, GPL-3.0; mcp-joern) need a JVM and a container. [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)

### Inferences
- Tree-sitter is the common extraction layer for open-source code graphs, because it is fast and covers many languages. Its limitation is that it resolves names syntactically, so cross-file calls through imports, overloads or dynamic dispatch can be wrong or missing. LSP (Serena) and SCIP (Sourcegraph, Blarify) and build-based trees (Moderne LST) trade setup cost for accuracy.
- Serena's adoption lead suggests practitioners value precise symbol navigation and editing more than persistent graph queries. This inference is based on star counts only.
- Operational weight matters for adoption. Tools requiring Neo4j or Memgraph servers, or JVM containers, are skipped by practitioners who want a single binary.

### Gaps
- Current GitHub star counts, commit activity and licenses were not verified directly on GitHub for Potpie, code-graph-rag, CodeGraphContext, GitNexus, Blarify or codebase-memory-mcp.
- No independent accuracy benchmark comparing these tools on the same repositories was found.

## Q4. How do these compare on graph-based versus vector-based versus LSP/symbol-based design?

### Takeaway
There are four design families: agentic search with no index (Claude Code), vector or semantic indexes (Augment, Qodo, Cognee hybrids), symbol-precise indexes (LSP in Serena, SCIP in Sourcegraph, LST in Moderne), and explicit knowledge graphs (Greptile, Tabnine, Bito, Atlassian, open-source Tree-sitter graphs). Practitioner consensus is that these are complementary: grep and agentic search handle exact strings and freshness, symbol indexes handle precise navigation, and graphs help with multi-hop and impact questions. Evidence for any one design being superior is mostly vendor-produced or anecdotal.

### Cited Findings
- **Agentic search with no index.** Boris Cherny said early Claude Code used RAG with a local vector database, but the team found that agentic search with Glob and Grep "generally works better". He cited the overhead and security downsides of an indexing step, at the cost of latency and tokens. He also said the evidence was "some internal benchmarks also, but mostly vibes". [I] — [OfficeChai](https://officechai.com/ai/claude-researcher-explains-how-agentic-search-performed-better-than-rag-for-code-generation/); [smartscope.blog](https://smartscope.blog/en/ai-development/practices/rag-debate-agentic-search-code-exploration/)
- **Vector or semantic index.** Augment frames its Context Engine as semantic search, and claims it improves Claude Code, Cursor and Codex by 30–80%. This is direct vendor counter-evidence to the "agentic search is enough" position. [V] — [Augment blog](https://www.augmentcode.com/blog/context-engine-mcp-now-live)
- **Graph versus vector argument.** Tabnine argues that code generation needs a knowledge graph rather than a search index, and that relevance should be computed by graph traversal from the working context. [V] — [Tabnine blog](https://context.tabnine.com/?p=40262)
- **Symbol-precise indexes.** SCIP gives Sourcegraph precise cross-repository definitions and references. Serena gets the same precision from live language servers. Moderne's LST adds full type attribution from the build. [V] — [Sourcegraph MCP](https://sourcegraph.com/mcp); [rywalker.com: Serena](https://rywalker.com/research/serena); [Moderne MCP overview](https://docs.moderne.io/user-documentation/agent-tools/mcp/overview/)
- **Division of labor.** A vendor-published post argues that agents should keep grep for strings and add a graph for structure, and that if all questions are single-hop string lookups a graph is overhead. [V] — [graphify.com](https://graphify.com/blog/code-knowledge-graph-vs-grep)
- **Hybrid tools.** GitNexus combines a graph with BM25 and optional embeddings, while CodeGraphContext is pure graph. The independent surveyor lists "graph versus embedding recall" as an unresolved open question. [I] — [wal.sh 2026 survey](https://wal.sh/research/2026-code-graph-mcp-survey/)
- **Token-cost evidence for graphs.** Reported savings are about 99% for call-site queries (codebase-memory-mcp), 3,400 versus 412,000 tokens for five structural queries (CodeGraph), and 47% per task on SWE-Bench Pro (Bito). All are tool-author numbers with unpublished or vendor methodology. [A]/[V] — [dev.to codebase-memory review](https://dev.to/andrew-ooo/codebase-memory-mcp-review-99-token-cut-for-code-agents-3d81); [dev.to CodeGraph review](https://dev.to/andrew-ooo/codegraph-review-pre-indexed-knowledge-graph-for-ai-agents-af1); [Bito](https://bito.ai/blog/swe-bench-pro-evaluation/)
- **Freshness trade-off.** Write-ups note that indexes lag behind edited files while direct file reads are always current. Augment's local mode and Greptile's continuous updates are vendor responses to this concern, while GraphRAG's batch re-indexing is the weakest case. [I]/[V] — [smartscope.blog](https://smartscope.blog/en/ai-development/practices/rag-debate-agentic-search-code-exploration/); [Augment MCP docs](https://docs.augmentcode.com/context-services/mcp/overview.md); [aicoolies](https://aicoolies.com/comparisons/lightrag-vs-graphrag)

### Inferences
- The table below summarizes the design families. It is the researcher's synthesis of the findings above.

| Design | Examples | Strength | Limitation |
|---|---|---|---|
| Agentic search, no index | Claude Code Grep/Glob, probe, ripgrep MCP | Always fresh, no setup, no data leaves the machine | Costs tokens and latency, and struggles with multi-hop questions in large codebases |
| Vector or semantic index | Augment, Qodo, Potpie similarity search, code-graph-rag embeddings | Finds code by meaning rather than name | Weak on exact relationships, needs re-embedding, and is a black box |
| Symbol-precise (LSP, SCIP, LST) | Serena, Sourcegraph, Moderne, Blarify | Compiler-accurate definitions, references and safe refactoring | Needs language servers or builds per language, and covers code only |
| Tree-sitter code graph | GitNexus, CodeGraphContext, code-graph-rag, codebase-memory-mcp, Aider repo map | Cheap, multi-language, supports call-graph and impact queries | Name resolution is approximate, and graphs get noisy on monorepos and generated code |
| Organizational knowledge graph | Atlassian Teamwork Graph, Glean, Unblocked, Tabnine, Bito | Links code to tickets, PRs, chat and docs, with permission trimming | Weak on code structure, mostly proprietary, and its quality claims are unverified |
| LLM-extracted GraphRAG | Microsoft GraphRAG, LightRAG, FalkorDB Code Graph descriptions | Captures concepts in unstructured text | Indexing is expensive and slow to refresh, and extraction is non-deterministic |

- No product found in this research offers a fully open, temporal knowledge graph that joins precise code symbols with tickets, PRs and ADRs. Commercial vendors (Tabnine, Bito, Unblocked) claim parts of this, which is a gap that a self-built system could target.

### Gaps
- No independent, controlled study comparing graph, vector and LSP retrieval for coding agents on the same benchmark was found.
- A primary Hacker News thread capturing practitioner sentiment on code knowledge graphs was not located. Only secondary references to HN discussion were found.
